# إنشاء نسخة مستقلة لكل عميل

القالب لا يحتوي بيانات أي عميل. كل عميل يحصل على **نسخة مستقلة** (كود + قاعدة بيانات + ملفات + `.env`).

## الخيار 1 — مستودع مستقل لكل عميل (موصى به)

مناسب عندما يختلف التخصيص كثيرًا بين العملاء أو يملك العميل مستودعه.

```bash
# من القالب الأم
git clone https://github.com/OWNER/laravel-ecommerce-starter.git client-acme
cd client-acme
git remote rename origin template          # نحتفظ بالقالب كمصدر للتحديثات
git remote add origin https://github.com/OWNER/client-acme.git   # مستودع العميل (خاص)
git checkout -b main template/main         # أو الفرع المعتمد من القالب
git push -u origin main
```

**تحديث العميل من القالب لاحقًا:**

```bash
git fetch template
git merge template/main          # راجع التعارضات؛ جرّب على نسخة تجريبية أولًا
```

## الخيار 2 — فرع لكل عميل داخل نفس المستودع

أبسط، لكنه يخلط عملاء في مستودع واحد (مشاكل خصوصية وصلاحيات). استعمله فقط إن كان المستودع خاصًا بك وحدك:

```bash
git checkout -b client/acme main
```

## ما يُخصَّص لكل عميل (دون تعديل الكود)

كل شيء من `/install` ثم لوحة الإدارة: الاسم، الشعار، الألوان، العملة، التواصل، طرق الدفع، الشحن، الصفحات.
**لا تضع** اسم العميل أو بياناته أو أسراره داخل الكود أو الـ commits.

## ما لا يدخل Git أبدًا

`.env`، `storage/`، `public/storage`، `public/build`، `vendor/`، نسخ قواعد البيانات، `CLIENT_HANDOFF` المعبّأ.

## خطوات تجهيز عميل جديد (مختصر)

1. أنشئ نسخة (الخيار 1) واملأ `CLIENT_HANDOFF.md` خارج المستودع.
2. جهّز الاستضافة والدومين وقاعدة بيانات **خاصة بهذا العميل**.
3. انشر (`DEPLOYMENT.md`) وضع `.env` الخاص به.
4. `migrate` ← `/install` ← أدخل بياناته.
5. أضف المحتوى، احذف البيانات التجريبية، نفّذ قائمة المراجعة.
6. وثّق: موقع الاستضافة، الدومين، موعد التجديد، جدول النسخ الاحتياطي.

## قواعد عزل مهمة

- قاعدة بيانات ومستخدم قاعدة بيانات **لكل عميل**.
- `APP_KEY` **مختلف** لكل عميل (لا تنسخ `.env` بين العملاء).
- لا تشارك مجلد `storage` بين عميلين.
